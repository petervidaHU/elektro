# apps/web - frontend

React Router v7 in **framework mode** (SSR) with **Mantine** UI. In production this
app is not served by Vite: `apps/api` serves the build output and the SSR request
handler from one Node process.

**What to build lives in [`docs/DEVELOPMENT_PLAN.md`](../../docs/DEVELOPMENT_PLAN.md)**
(the single source of truth; see the root `CLAUDE.md`). For frontend work, the
relevant sections are:
- §3, the UI/UX design:
  - principles and navigation;
  - the page inventory with routes and access levels (§3.3);
  - user journeys J1–J9 (§3.4);
  - feedback and system states (§3.5);
  - the mastery model (§3.6).
- §1.3, the lesson Markdown blocks the reader renders.
- §2.5, the practice screen behaviour: step feedback, the tolerance shown to the
  student, hints, `<NumericKeypad>`, session length.

New routes and pages must match §3.3. If a page needs to differ from the plan,
update the plan in the same PR.

## Layout

```
app/root.tsx          document shell, MantineProvider, ErrorBoundary
app/routes.ts         route config (every app route lives under /:locale)
app/entry.server.tsx  SSR entry; creates one i18next instance per request
app/entry.client.tsx  hydration entry
app/i18n/             i18next setup, locale helpers, hu resources
app/routes/           route modules
app/lib/api.ts        typed calls to /api from loaders and actions
app/lib/calculators.ts the calculator registry (list, page loader); never hard-code calculators
app/components/content/ forms of the content-management pages (/teacher/content)
app/theme.ts          touch-first Mantine theme (MIN_TOUCH_TARGET)
```

## Rules

- **No hard-coded user-facing text.** Every string comes from an i18next key in
  `app/i18n/locales/<locale>/common.json`. API errors arrive as codes and are
  rendered via `t("error.<CODE>")`. `app/i18n/i18n.test.ts` fails when a topic,
  content status or error code has no translation.
- **The locale lives in the URL** (`/hu/...`). Read it with `localeFromPathname`
  and build links with `localePath(locale, path)` - never from a header or
  cookie, and never assume `hu`.
- **Touch-first.** Every learning interaction must be completable on a phone
  with touch only, no keyboard:
  - interactive elements are at least `MIN_TOUCH_TARGET` (44px) tall;
  - numeric entry uses `NumberInput` with steppers, or a `Select` over the
    allowed values (e.g. the standard cross-section series) - never a field that
    can only be filled by typing;
  - choices use `SegmentedControl` / `Select`, not free text;
  - layouts are single-column on `base` and only widen from `sm` up.
- **Formatting is locale-aware.** Use `formatNumber` / `formatQuantity` /
  `formatPercent` from `@elektro/shared` so Hungarian renders a decimal comma
  (`2,5 mm²`). Never format numbers by hand.
- **Calculations never live here.** Import the engine from `@elektro/shared`, so
  the browser, SSR and the API all compute the same result.
- **Server-side API calls go through `app/lib/api.ts`** (`apiFetch`, `apiUrl`,
  `forwardedHeaders`): loopback to the API plus the browser's session, CSRF and
  client-IP headers. Never fetch the public URL from a loader or action - behind
  the reverse proxy it may not resolve.
- **The signed-in user** is loaded once by `routes/locale-layout`; read it with
  `useLayoutData()`. Login-only pages call `requireUser(request, locale)` in their
  loader, which sends guests to `/login?returnTo=...` (validated by `safeReturnTo`).
- **Teacher/admin pages** call `requireStaff(request, locale)` in their loader.
  Destructive actions use `ConfirmButton` (two taps). Authoring forms may need
  typing; the touch-only rule applies to learning interactions.
- **The UI is not a security boundary.** Hiding a control is a convenience; the
  API re-checks the role on every request.

## Development

`npm run dev` starts the Vite dev server on 5173 and proxies `/api` to the API on
3000. Route types are generated by `react-router typegen` (run automatically by
`npm run typecheck`); import them as `import type { Route } from "./+types/<route>"`.
